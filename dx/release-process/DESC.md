# 发布流程

## 是什么
把已合入主干的变更安全推向用户的执行流程：发布前核对检查单，先灰度小流量验证，通过后再全量发布。

## 作用
约束"什么时候可以发、怎么发、发到什么程度"：用统一检查单避免漏项，用灰度→全量的两级节奏把发布风险控制在小范围内；agent 执行部署/发布类任务时按此流程走。

## 与父级的关系
本 dx 是根单元（father: null）。原先从属 git-workflow（管"代码怎么合入主干"），2026-11-10 经用户确认改为根单元；上游代码合入约定如后续需要，以独立 dx 或 git 帮助为准。
