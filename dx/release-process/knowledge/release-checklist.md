# 发布检查单

发布前：
- 变更已合入主干，且主干 CI 全绿（构建、单测、lint 均通过）。
- 本次发布的变更范围明确（feature/fix 列表、涉及模块），无夹带未确认的改动。
- 数据库/配置/依赖变更已准备就绪，且兼容回滚。
- 回滚方案就绪：知道上一稳定版本是谁、怎么退。

灰度中：
- 按计划比例放量（如 1% → 10% → 50%），每档观察足够时长后再放下一档。
- 盯核心指标：错误率、延迟、资源占用、核心业务转化无明显劣化。
- 出现异常立即停止放量并回滚，不带着问题继续灰度。

全量后：
- 复查核心指标，确认稳定。
- 通报发布结果（成功/失败/回滚），归档本次发布记录。
