# 教程基础排版规范

以下为强制条目，违反视为错误。

## 结构
- 教程文件必须以 YAML frontmatter 开头承载元数据：`title`、`series` / `chapter`（系列教程）、选题卡三要素（`topic` 一句话主题 / `audience` 读者画像 / `outcome` 预期收获）、`environment` 与 `date`；选题卡不用 HTML 注释或正文承载。
- 一篇教程只有一个 H1（教程标题）；章节用 H2、小节用 H3，不跳级、不用标题当加粗效果。
- 文首必须包含：适用版本/环境说明（软件名 + 版本 + 系统）与「你将学会什么」简述。
- 篇幅不设字数上限，但必须避免啭嘨：每个句子都要有信息量，铺垫、重复、客套与空洞过渡一律删除；长短以讲清楚为准，不以凑字或求短为准。
- 操作步骤用有序列表，每步一个动作；并列概念用无序列表。

## 中英文混排
- 中文与英文单词、数字之间加一个空格：写「使用 Python 3 编写」，不写「使用Python 3编写」。
- 中文语境用全角标点；英文句子、代码与命令内部保持半角标点原样。
- 专有名词大小写保持官方写法（GitHub、macOS、iOS）。

## 代码与命令
- 代码块必须标注语言（如 ```bash、```python）；终端命令块区分命令与输出。
- 文件名、命令、键名、字段名等一律用行内代码格式（反引号）。
- 需要读者替换的占位符统一用 `<大写描述>` 形式，如 `<你的项目路径>`。

## 图片与链接
- 截图裁剪到关键区域，紧邻对应文字说明放置；图片 alt 文本必填。
- 外部引用一律给出可点击链接，链接文字写目标内容，不用「点这里」。
- 警示信息（易错点、不可逆操作）统一用 `> ⚠️` 引用块，置于相关步骤之后。

## 术语
- 同一概念全篇只用一个叫法；术语首现给出全称与解释，后文用统一简称。
