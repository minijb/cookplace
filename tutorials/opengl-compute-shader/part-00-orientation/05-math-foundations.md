# 第五章：向量、矩阵、点积、叉积与齐次坐标

适用环境：C++17、CMake 3.21+ 和 GLM。本章示例不需要窗口、GPU 或 OpenGL Context；所有计算都在 CPU 上完成，并由 CTest 检查结果。

你将学会：

- 区分位置、方向与向量，并计算向量加法、长度和归一化。
- 用点积判断方向关系，用叉积构造垂直方向。
- 理解为什么三维图形常使用 4×4 矩阵和四维齐次坐标。
- 解释 `w = 1` 的点与 `w = 0` 的方向在平移矩阵下的不同结果。
- 使用 GLM 验证变换顺序，理解矩阵乘法通常不满足交换律。

完整示例位于 [code/part-00-05-math](../code/part-00-05-math/)。本章不是完整线性代数课程，只建立后续渲染会直接使用的概念和计算方法。

## 向量：既有大小，也有方向

三维向量可以写成：

\[
\mathbf{v} = (x, y, z)
\]

同样的三个数可以表达不同含义：

- **位置**：某个点相对于原点的位置，例如顶点 `(1, 2, 3)`。
- **方向**：朝向，例如 Camera 的 Forward 或表面的 Normal。
- **位移**：从一点到另一点的变化量。
- **缩放因子**：每个轴分别缩放多少，例如 `(2, 2, 2)`。

GLM 中可以用 `glm::vec3` 保存这些量。类型相同不代表语义相同：位置和方向在齐次坐标下会受到不同处理，本章后面会看到这一点。

## 向量加法与标量乘法

向量加法按分量进行：

\[
(a_x,a_y,a_z)+(b_x,b_y,b_z)=(a_x+b_x,a_y+b_y,a_z+b_z)
\]

例如，物体当前位置加上本帧位移，就得到新位置。

标量乘法同样按分量进行：

\[
2(1,2,3)=(2,4,6)
\]

如果它表示方向，乘正数会改变长度但不改变朝向；乘负数还会反向。

示例检查 `(1,0,0) + (0,1,0) = (1,1,0)`。这类分量计算看起来简单，但它们是理解 Camera 移动和粒子运动的基础。

## 长度与归一化

向量长度使用欧几里得范数：

\[
\|\mathbf{v}\|=\sqrt{x^2+y^2+z^2}
\]

例如 `(3,4,0)` 的长度为 5。归一化就是保持方向不变，把长度变成 1：

\[
\hat{\mathbf{v}}=\frac{\mathbf{v}}{\|\mathbf{v\|}}
\]

所以：

\[
\operatorname{normalize}(3,4,0)=(0.6,0.8,0)
\]

归一化常用于：

- 把 Camera 方向变成单位向量。
- 让光照中的 Normal、Light Direction 具有可比较的长度。
- 避免速度向量长度意外影响位移大小。

> ⚠️ 零向量没有可归一化的方向。对 `(0,0,0)` 直接归一化不能得到有意义的单位方向，实际代码应先检查长度。

示例用 `glm::length` 和 `glm::normalize` 验证结果，并再次计算归一化后的长度是否接近 1。

## 点积：两个方向有多一致

三维点积为：

\[
\mathbf{a}\cdot\mathbf{b}=a_xb_x+a_yb_y+a_zb_z
\]

它也可以写成：

\[
\mathbf{a}\cdot\mathbf{b}=\|\mathbf{a}\|\|\mathbf{b}\|\cos\theta
\]

其中 \(\theta\) 是两个向量的夹角。因此，当两个向量都是单位向量时，点积直接给出夹角余弦：

| 点积 | 单位向量的方向关系 |
|---|---|
| 接近 1 | 方向几乎相同 |
| 接近 0 | 接近垂直 |
| 接近 -1 | 方向几乎相反 |

示例使用 X 轴 `(1,0,0)` 和 Y 轴 `(0,1,0)`，点积为 0，因为它们互相垂直。

后续 Phong 光照会用 Normal 与 Light Direction 的点积估计表面朝向光源的程度；聚光灯也会用方向点积判断 Fragment 是否位于光锥中。

如果向量没有归一化，点积还包含长度因素，不能直接把数值当作纯夹角余弦。

## 叉积：构造垂直于两个向量的方向

三维叉积写作：

\[
\mathbf{a}\times\mathbf{b}
\]

结果向量同时垂直于 \(\mathbf{a}\) 和 \(\mathbf{b}\)，长度与二者张成的平行四边形面积相关。

在右手坐标约定下：

\[
\mathbf{x}\times\mathbf{y}=\mathbf{z}
\]

示例验证：

```cpp
glm::cross(
    glm::vec3{1.0F, 0.0F, 0.0F},
    glm::vec3{0.0F, 1.0F, 0.0F});
```

结果是 `(0,0,1)`。

叉积常用于：

- 根据三角形两条边计算表面 Normal。
- 根据 Camera Forward 和 World Up 构造 Right 向量。
- 构造互相垂直的局部坐标轴。

**叉积不满足交换律。** 交换顺序会让结果反向：

\[
\mathbf{a}\times\mathbf{b}=-(\mathbf{b}\times\mathbf{a})
\]

所以三角形顶点绕序和 Camera 轴构造顺序都很重要。

## 矩阵：把变换写成统一运算

矩阵可以表达旋转、缩放和投影等变换。三维线性变换可以使用 3×3 矩阵，但为了把平移也纳入同一种乘法，三维图形通常使用 4×4 矩阵。

在本课程采用的“矩阵乘列向量”写法中：

\[
\mathbf{p}' = M\mathbf{p}
\]

矩阵在左，列向量在右。GLM 示例也采用这种写法：

```cpp
const glm::vec4 result = transform * glm::vec4{1.0F, 2.0F, 3.0F, 1.0F};
```

现在不需要手算完整 4×4 矩阵，但要能区分旋转、缩放、平移和投影的不同目的。

## 齐次坐标：为什么多出一个 w

齐次坐标用 `(x,y,z,w)` 表示三维量。对常见仿射变换，可以先这样理解：

- `(x,y,z,1)` 表示一个**位置点**。
- `(x,y,z,0)` 表示一个**方向或位移**。

这个区别使平移矩阵能够只移动点，而不改变纯方向。

### 点会被平移

示例创建向 `(10,20,30)` 平移的矩阵：

```cpp
const glm::mat4 translation =
    glm::translate(glm::mat4{1.0F}, glm::vec3{10.0F, 20.0F, 30.0F});
```

点 `(1,2,3,1)` 变换后成为 `(11,22,33,1)`。

### 方向不被平移

方向 `(1,2,3,0)` 经过同一个矩阵后仍为 `(1,2,3,0)`。这符合直觉：把整个世界平移，不会改变“向上”或“向右”这种纯方向。

> ⚠️ Normal 是方向，但不能因此认为任意变换下都只需设置 `w = 0`。非均匀缩放时，Normal 通常需要专门的 Normal Matrix；光照章节会单独解释。

## 矩阵乘法顺序为什么重要

矩阵乘法通常不满足交换律：

\[
AB \ne BA
\]

在列向量写法中，最靠近向量的变换先执行：

\[
T S \mathbf{p}
\]

表示先缩放 \(S\)，再平移 \(T\)。

示例从点 `(1,0,0)` 开始，先缩放 2 倍，再按 `(10,20,30)` 平移：

\[
T S\mathbf{p}=(12,20,30)
\]

如果交换矩阵顺序：

\[
S T\mathbf{p}=(22,40,60)
\]

第二种顺序先把点平移到 `(11,20,30)`，再把包括平移在内的结果放大 2 倍，所以得到 `(22,40,60)`。两个结果不同，不是 GLM 出错，而是变换顺序确实不同。

## GLM 的角度与浮点注意事项

- `glm::rotate` 的角度使用弧度；示例用 `glm::half_pi<float>()` 表示 90°。
- 如果只有角度值，可使用 `glm::radians(90.0F)` 转换。
- 浮点计算存在误差，测试使用小范围误差比较，不直接要求每个结果逐位相等。
- 本课程默认使用 GLM 的 OpenGL 风格矩阵约定；切换左手系或深度范围宏时，需要同步检查投影代码。

## 常见错误

| 错误 | 修正思路 |
|---|---|
| 把点积结果直接当角度 | 单位向量点积得到的是余弦；角度还需要反余弦并注意数值范围 |
| 交换叉积顺序却期望相同结果 | 叉积交换后会反向 |
| 对零向量归一化 | 先检查长度，定义零输入的处理策略 |
| 把方向当位置平移 | 方向使用 `w = 0`，位置使用 `w = 1` |
| 把 `T * S` 读成先平移 | 列向量约定下，右侧靠近向量的变换先执行 |
| 把角度值直接传给 `glm::rotate` | 先转换为弧度 |
